# Ledger · 产品需求文档（PRD）

> 版本 v1.0 · 2026-08-22 · 状态：已确认定稿
>
> 配套文档：[ARCHITECTURE.md](./ARCHITECTURE.md)（技术架构与全部决策记录）

## 1. 愿景与定位

Ledger 不是一款记账应用，而是一个**个人财务数据操作系统**：

- **内核**：一套自洽的收支数据内核，提供记账、修订、作废、统计的完整闭环，以及插件宿主能力
- **插件**：一切扩展能力皆插件——交易类型、动态字段是领域插件；CLI、MCP、HTTP 是通信插件
- **多入口**：同一份数据与业务逻辑，被 CLI、MCP、HTTP 等多种方式访问；将来新渠道 = 新插件，内核零改动

### 第一原则（产品层面的表述）

1. **内核自洽**：不装任何插件，系统依旧自运转。基础收支数据（方向、金额、时间、来源、记录者）自洽完整。基础类型插件虽默认必装，但设计思想上内核不依赖任何插件的存在
2. **数据自包含**：每条数据冗余携带自己的语义（direction、扩展字段的值），插件可死、可换、可卸载，历史数据永不失效
3. **插件广职权**：服务于个人，普通插件与内核深度互信、职权范围广，无权限审计负担
4. **能力分级**：插件管理能力（生命周期管控、安装管理）是内核的独立能力面，仅授予白名单内的核心维护插件；管理入口不唯一（CLI 是第一个，不是唯一的）

## 2. 用户与场景

- **用户**：单人多 recorder。recorder 为自由标识：`me`（本人）、`bot:<id>`（自动化身份，如 `bot:claude`）
- **无账号体系**：不做注册登录，不做多用户隔离
- **典型场景**：
  - 终端快速记一笔收支（CLI，高频）
  - 浏览器图形界面记账、浏览流水与统计（WebUI，面向用户的主界面）
  - 通过 AI 客户端（MCP）自然语言记账与查询
  - bot 自动化记账（订阅事件、定时任务）
  - 事后修订、作废记错的账，且历史可追溯
  - 按月/方向/类型统计

## 3. 核心概念

| 概念 | 说明 |
|---|---|
| Entry | 一条账目记录，系统唯一的聚合根 |
| direction | 内核语义：`income` / `expense`。统计的唯一依据，永不依赖插件 |
| type | 可空的扩展类型（如 `salary`、`withholding`），由类型插件或用户注册，注册时强制声明 direction 映射 |
| Money | 金额 = 最小货币单位整数（分）+ ISO 4217 货币码；多币种只记录不折算 |
| extra | 动态扩展字段的载体（JSON）。用途、付款平台、接收平台等均在此扩充 |
| source | 记录来源（`cli` / `mcp` / `http` / …），由调用链自动注入，不由用户填写 |
| recorder | 记录者（`me` / `bot:<id>`），来自调用上下文，可覆盖 |
| book | 账本。数据结构预留 `book_id`（默认 `default`），第一版不暴露多账本功能 |
| 插件 | 一切扩展的统一形态：领域插件（类型/字段）、通信插件（CLI/MCP/HTTP） |

## 4. 基础数据模型（业务视角）

一条 Entry 的固定内核字段：

- **产生时间** `occurred_at`（业务发生时间，允许未来值——预扣、预订场景）与 **入库时间** `recorded_at` 分离
- **记录来源** `source`、**记录者** `recorder`（自动注入）
- **方向** `direction`（income / expense）
- **金额** `amountMinor` + `currency`
- **账本** `bookId`（预留，默认 `default`）

其余一切属性为扩展：`type`（注册制）+ `extra`（动态字段，运行时可扩充，支持代码扩充与用户运行时注册两条路）。

数据纪律：

- 金额恒为正整数，方向由 direction 表达，不用负数
- 不提供物理删除；作废走软删（void），默认不参与统计但可查
- 修订 = 原行可改 + 修改前完整快照留痕（谁、从哪入口、何时、为什么改）
- 每条记录写入时锁定当时的 `schema_version`，作为未来数据迁移的锚点
- 未注册字段允许写入 extra（数据自包含哲学）；入口层可提供严格模式拒绝未注册字段（CLI 的 `--strict`）

## 5. 功能需求（MVP）

### 5.1 内核能力

- 记账（add）：校验 → 落库 → 发布 `EntryRecorded`
- 修订（revise）：可改任意字段，前像快照入修订历史表，发布 `EntryRevised`
- 作废（void）：软删 + 原因，发布 `EntryVoided`
- 查询（query/list）：按时间、方向、类型、recorder、book 过滤
- 统计（stats）：按月 / 按方向 / 按类型汇总
- 插件宿主：发现、加载、激活、停用、热替换（L1）、隔离重引导（L2）、崩溃监护
- 统一注册表：`entry.type` / `entry.field` / `adapter` 扩展点，将来 `report`、`currency.provider`、`importer` 等只是新增种类
- 事件总线：进程内发布订阅，订阅随插件停用自动退订
- 能力面：HostAPI（全插件）+ AdminHostAPI（白名单特权插件）
- 插件间服务：插件可向其他插件提供/消费服务（如 user 插件提供 userId），拓扑排序加载，可选依赖自行降级

### 5.2 插件体系（两梯队）

核心插件的定位：**不只是可行性验证，而是必要功能 + 为后续插件提供开发基础能力**（如 user 插件提供 userId）。

**第一梯队：入口插件**（基础架构独立验收后立即实现，顺序即依赖序：cli → http → webui）：

| 插件 | 形态 | 能力 |
|---|---|---|
| plugin-cli | 冷引导混合 | 混合自动模式：宿主在→本地 socket RPC（毫秒级），不在→冷引导直调。具备 AdminHostAPI：插件生命周期管控、安装管理。动态字段的 CLI flag 从注册表自动生成 |
| plugin-http | L2 worker | 纯 API 入口（程序化访问，无 UI）；L2 热更新与 supervisor 的实战验证 |
| plugin-webui | L2 worker（前后端一体） | 面向用户的主界面：serve 前端 shell 产物 + 统一调用协议 HTTP 网关 + UI 插件文件服务。内部自成 UI 插件宿主（见 5.4，分形插件架构） |

**第二梯队：核心功能与能力提供者**：

| 插件 | 形态 | 能力 |
|---|---|---|
| plugin-user | L1 + 服务提供者 | 用户/访问者体系（用户 id、用户名等基础信息，human/bot）；提供 `user` 服务供前端展示身份、供后续插件获取 userId |
| plugin-core-types（完全体） | L1 | 类型体系：大类型 + 小类型层级、lucide 图标、付款平台等枚举字段——记账表单与统计的完整分类语义 |
| plugin-webui-core-views | UI 插件（webui 内） | 记账表单、流水列表、Entry 详情——最小可用；统计图表归 plugin-dataviews，shell 自身零业务视图 |
| plugin-dataviews | UI 插件 + 内核侧查询 | 数据视图：月度趋势、类型分布、付款平台分布、recorder 维度等多维展示 |
| plugin-snapshot | L1 + 服务提供者 | 快照：按粒度（全库 / 指定账本）备份与回迁（恢复到指定快照） |
| plugin-mcp | 冷引导独立进程 | 被 MCP 客户端 spawn，stdio 通信，像 CLI 一样组装内核；热更新 = 进程重启 |

### 5.3 动态字段与类型的两条扩充路径

- **代码扩充**：插件在 `activate()` 中注册 type/field
- **运行时扩充**：用户经任意入口执行注册命令（本质为内核管理的元数据通道），与插件贡献、并存三来源（`origin: plugin | user`），同一张注册表

### 5.4 WebUI 与 UI 插件系统（分形插件架构）

WebUI 是面向用户的必要插件，同时自身内部复刻同一套插件哲学——**分形**：

- **对内核而言**，plugin-webui 是一个 L2 插件（前后端一体）：后端起 HTTP server（serve 前端产物 + 统一调用协议网关 + UI 插件文件），前端是 React SPA
- **对浏览器而言**，前端 shell 是一个 UI 插件宿主：UI 插件贡献页面、仪表盘卡片、详情面板、设置区块，运行时动态加载、可启停、可热替换
- **shell 零插件自洽**：空 shell 可运行（仅显示插件管理），装上 webui-core-views 才有记账界面——镜像内核第一原则
- **前后端桥**：UI 插件通过 client（统一调用协议 over HTTP）访问内核，与 CLI/MCP/HTTP 一视同仁，无特权通道
- **同源动态表单**：field_defs 注册的枚举字段在 WebUI 自动渲染为下拉、日期字段渲染为日期选择器——与 CLI flag 生成、MCP tool schema 生成同源，注册一个字段所有入口同时获得支持

前端技术栈：Vite + React + Tailwind CSS v4 + shadcn/ui + zustand。

## 6. 非目标（明确不做）

- 多用户、账号体系、权限隔离
- 插件签名、权限审计、沙箱（仅保留轻量能力分级白名单）
- 汇率折算与本位币报表（仅留 `currency.provider` 扩展点）
- 物理删除数据
- 插件市场与生态治理
